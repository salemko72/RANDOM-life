# Android testing release 0.19.0 (versionCode 2)

Project: `@salemko/random`, package `com.salemko.randomlife`.

The web correction smooths the READ image silhouette. Native startup now loads
the installed HTML asset from a local file instead of importing a 49 MB JSON
string into Hermes and sending it as a WebView property. The Android export has
a separate HTML asset and a roughly 1.5 MB Hermes bundle. Local profile, language,
history and favorites still use the existing native storage bridge. The reserve
catalog contains 100 published items with local images.

This removes a large startup allocation; it does **not** establish the cause of
the previously reported device crash. Device logs or a successful repeat test
on that phone are still needed. Browser tests of prepared local files use HTTP
because the managed browser policy blocks `file://` navigation; they are not a
physical Android launch test.

## Build and signing

From the repository root run `npm ci` (including dev dependencies and postinstall),
then `npm test`, `npm run typecheck`, and `npm run check:expo`.
The postinstall generates `apps/client/src/generated/preview.html`; do not omit it.

From `apps/client`, using an existing authenticated EAS CLI:

```sh
eas build --platform android --profile preview --freeze-credentials
eas build --platform android --profile production --freeze-credentials
```

- `preview` produces a signed APK for direct installation.
- `production` produces a signed AAB for Google Play, with the existing EAS
  Android credentials. Do not generate a replacement signing key.
- Both represent the same release/versionCode. Increase versionCode for the next
  Play upload; Play rejects reuse of an already uploaded versionCode.
- Native directories are generated by EAS prebuild; locally ignored Gradle edits
  are not part of the upload. Keep release settings in Expo configuration.
- Builds do not submit or publish to Google Play automatically.

## Before inviting testers

Install the APK on the phone that previously crashed. Check cold launch, name
entry and optional profiling, wheel and all five categories, full images,
favorites after restart, external sources, and launch in airplane mode. Confirm
the reserve badge, images, and automatic return to D1 when connectivity returns.
Capture logcat if it crashes (`scripts/android-diagnostics`).

Upload the AAB in Play Console's internal testing track first and review its
automated pre-launch/device reports. Complete the store listing, content rating,
target audience, ads declaration, Data safety and app-access declarations based
on actual behavior. Consumer content needs no Studio password. Then configure
the closed testing track required by the account's production-access checklist.
Internal and closed testing are different tracks.

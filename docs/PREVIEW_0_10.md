# Preview 0.10: ZIP-only content intake and low-phosphate preference

New content is imported through a ZIP at the top of Studio. No source text, category choice, prompt copy, or review checkbox is required before import. Category, image and both languages come from the validated archive. Prompt preparation is an optional collapsed section; raw imported data is read-only diagnostics. There is no manual JSON paste or standalone image picker for new items.

The chosen archive filename remains visible. A persistent status identifies reading, saved draft or rejection, with detailed field errors. Invalid archives preserve the current editor and library; duplicate imports never overwrite an existing item. Image and draft write atomically in local IndexedDB. The user's reported particular ChatGPT ZIP has not been supplied, so archive-specific diagnosis remains pending.

Low-phosphate is a dietary preference, not an extra wheel category. `Profile.lowPhosphateDiet` persists in browser/native profile storage; older profiles default false. English and BHS registration/editing expose it. Recipe JSON supports optional `phosphateAssessment` with suitability low/not-low/uncertain, bilingual notes, reviewed flag, optional sourced phosphorus mg/serving and evidence URL. The existing D1 data JSON stores these fields without a destructive table migration; local D1 round-trip and publication checks are tested. The preview remains browser-local and no remote database or paid service is enabled by this change.

The prompt requests evidence-based assessment with uncertainty when data is insufficient. It must not invent phosphorus values or clinical thresholds, confuse phosphate with potassium/sodium/protein restrictions, or assume every kidney patient needs the same diet. ZIP import resets phosphate review. Studio exposes separate human confirmation; confirming a low assessment adds the canonical `low-phosphate` dietary tag.

Both the preview recommender and shared API recommendation contract reject unreviewed/missing phosphate assessments for this preference. Publication of a tagged recipe also requires reviewed low suitability. Existing demo recipes are not relabeled automatically, so the low-phosphate demo pool may be empty until reviewed content is available. Preferences never silently relax when the pool is empty. This label is inspiration within an individual's dietary plan, not a blanket kidney-safe claim.
